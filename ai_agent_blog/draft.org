## 1. コンセプト・全体像

- **事前学習済み TTS を VC に作り変える**: テキスト → 音声の DiT に「入力音声のフレーム単位の内容条件」を足して VC 化
  - 「テキストの代わりに入力音声から内容と話し方を取る」だけで、既存の学習ループ・部品の大半を流用できた
- **書き起こし不要の自己教師学習**: 「声色を消した入力から同じ発話を復元する」だけ → TTS で一番重い書き起こしの点検が要らない
- **言葉にならない音 (笑い・息・泣き) が時間軸のまま通る**: 絵文字や書き起こしで位置を指定する必要がない、というフレーム単位 VC の強み
- **ワンショットの声色再現**: ワンショット音声クローン TTS をベースにしているので、VC でも変換先の参照音声 1 本で声色を再現できる
  - 変換先ごとの学習は不要。RVC のように話者ごとにモデルを作る方式との違いとして書ける
- **さらに再現度を上げたいときは話者 LoRA** (学習時間 10 秒程度、7 章)。「まずワンショット、足りなければ 10 秒の追加学習」という二段構え
- 構成図ネタ: 元の TTS と VC 版の差分を色分けした図 (凍結 / 追加学習 / LoRA / 使わない部品)。部品名は一般名詞にする
- 技術デモ動画 https://youtu.be/Eq9_9CRA5zI  
  

## 2. 学習不要の基準 (ベースライン) で分かったこと

- **カスケード VC (ASR → TTS)**: 声色は変わるが抑揚 (f0_corr 0.19〜0.36) と非言語音 (nv_corr −0.03) が消える
  - 「テキストを経由すると何が失われるか」を定量化する物差しとしての位置づけ
- **SDEdit 方式 (コーデック latent に途中までノイズ → 再生成)**: 「ちょうど良い t0」が存在しない
  - t0 ≤ 0.75 では声色ほぼ不変、t0 = 0.9 で急に声色が変わるが抑揚が消える
  - 仮説: このモデルでは声色が生成の初期 (ノイズが多い段階) で決まる
- **テキスト条件で学習された TTS は、テキストなしでは言葉を保てない** (テキストなし t0=0.6 で CER 0.59)
- → 「声色を変える」と「抑揚・タイミング・非言語音を残す」は学習なしでは両立しない、という結論までの流れ

## 3. 本命: ContentAdapter による VC 化

- 撹乱した WavLM 特徴 (層 6/9/12) → ContentAdapter → DiT の入力射影の出力に加算
  - 出力層をゼロ初期化 (ControlNet と同じ発想) → 学習開始時は元の TTS と同じ動作
  - WavLM とコーデック latent がどちらも約 25 Hz で、長さ合わせが端数調整だけで済む
- 学習対象は ContentAdapter + DiT の LoRA のみ。DiT 本体・話者エンコーダ・コーデックは凍結 (VRAM 8 GB・7 分で 1 回の学習)
- 声色の参照には「同じ話者の別の発話」を使い、入力の声色をコピーする近道を防ぐ
- 最初の結果: 声色・抑揚・非言語音は良いのに **音韻が崩れる** (CER 0.67。リズムは合っているのに言葉が聞き取れない実例が面白い)

## 4. 声色の漏れとの戦い

- 声質撹乱 (ピッチ・フォルマント・EQ) をかけても **WavLM 特徴から話者を 93% 当てられる** (撹乱なし 94%) という事実
- 対策の候補の比較: 別人の声に変えた入力で学習 / k-means 離散化 / ASR エンコーダ特徴 / 話者敵対学習 (GRL)
  - 「スタイル学習で GRL を使ったら z が一定に潰れた」失敗談
- 女→男の変換で元の声色が残る問題 (低い声への sim_tgt 0.73、カスケードは 0.83)

## 5. テキスト・内容・スタイルの統合

- 内容 (常に) + テキスト (ASR 書き起こし、非言語音は絵文字、50% で落とす) + スタイル (自作の StyleEncoder を流用、30% で落とす)
  - 音韻はテキスト経路 (元の TTS が得意)、タイミング・抑揚・非言語音は内容条件、という役割分担
  - CER 0.48 → **0.04** に改善
- **textauto**: 言葉を含む書き起こしのときだけテキストを使い、絵文字だけのときは内容条件に任せる小技
- 意外な発見: **テキストを 50% で落として学習すると、テキストなしで使ったときは内容のみの学習より悪い**
  (テキストがあると、内容条件から音韻を読む学習が進みにくい)
- 話者数を 6 → 84 人に増やすだけで内容のみ VC の CER 0.67 → 0.48

## 6. 評価設計の話 (地味だが需要あり)

- 5 つの軸: 声色 (WavLM-SV) / 言葉 (Whisper CER) / 抑揚 (正規化対数 F0 の相関) / 非言語音 (AST) / 試聴
- **指標の信頼性を測った話**: 同じ条件で 2 回変換すると GPU の揺らぎで f0_corr が ±0.11 も変わる → ±0.1 の差は判断できない
- **声色の類似度は言葉が崩れた出力ほど高く出る**落とし穴 (意味のない発声で 0.89) → CER の近い方式どうしでのみ比較
- 非言語音の保持を直接測る指標の自作: AST の非言語音クラス確率を 1 秒窓で比較 (`nv_corr` / `nv_recall`)
  - 少数のサンプルでもカスケードとフレーム単位 VC の差がはっきり出た
- 評価セットの設計: 変換元 3 区分 (普通 / 非言語音中心 / 感情コーパス) × 変換先 3 区分 (学習済み / 未学習・低い声 / 未学習・高い声)、120 組 × 2 シード、95% 区間の目安つき
- ASR の「でっち上げ」で CER が 6 を超える外れ値 → 1 件ごとに 1.0 で切り詰める
- 学習データの「見たことのない声」を本当に未学習にするための話者単位の分割 (発話単位の分割では漏れる)

## 7. 声色の再現度を上げる手法の比較 (効いたもの・効かなかったもの)

- **効いた: 話者 LoRA** (推論時に変換先の声で VC の LoRA を追加学習。学習時間は 10 秒程度)
  - ワンショット (参照 1 本・学習なし) で足りない声に対する「追い込み」の位置づけ
  - 学習に使っていない音声で測っても、低い声への sim_tgt 0.715 → 0.888
  - ステップを増やすと声色は上がるが言葉が崩れる (CER 0.245 → 0.357 @500)、非言語音は 100 ステップが最良 → 既定 100 に
- **少し効いた: 参照音声を増やす** (複数参照の latent をつないで話者エンコーダへ)
  - ただし参照を長くすると言葉が崩れやすい疑い
- **効かなかった**:
  - 話者条件の K/V 倍率 (条件を強める) → 1.5 でノイズで崩れる
  - Speaker Inversion (話者トークンの最適化) → 損失は下がるが類似度は変わらない
  - latent の統計合わせ (AdaIN 方式) → 元の声色のまま
  - 近傍フレームの入れ替え (kNN-VC / RVC の検索に相当) → 一部の声で改善、でもノイズで崩れる
- 考察: 声色は latent の **時間変化** に表れる → フレーム単位の操作では無理、時間方向を扱える自己注意を学習する話者 LoRA が効いた理由と整合
- RVC との対応表 (検索 ≒ kNN、話者ごとのデコーダ ≒ 話者 LoRA、RVC にあって本研究に無いのは明示的な F0 条件)

## 8. 判断・見送りの記録

- **大きいモデルに乗り換えなかった理由**: 約 4 倍の規模で 16 GB GPU では学習が厳しい。声色の改善はわずかで、参照音声を長くする効果の方がはるかに大きい
  (具体的なモデル名・モデルカードの数値は出さず、傾向だけ書く)
- データのグループ分け: 「表現用」(7 話者・3.4 時間、感情・非言語音) と「多様性用」(78 話者・0.35 時間、声質の多様性) を分けて混ぜる割合を制御

## 9. 実験の進め方・環境まわり (ツールの紹介ではなく、研究の回し方として)

- 試聴用の Web UI を自作して、数値に出ない違いを耳で確かめるループを回した話 (UI 自体は非公開・スクリーンショットも出さない方が無難)
  - 利用者の試聴の所見が次の手法 (話者 LoRA) につながった流れ
- 長い入力は無音で区切って変換し、元のタイミングで並べ直す工夫
- 推論時に LoRA を一時的に差し替え・無効化して、同じモデルで VC と元の TTS を比べる工夫
- GPU 実行をすべて `make` 経由にしている運用 (AI コーディングエージェントのサンドボックス外で動かすため・メモリ上限つき)
- 長い録音を自動で切り出して学習データにする流れ (書き起こし不要なので集めた音声を全部使える)

## 13. 鍵となる技術のまとめ (シリーズの導入・総まとめ向け)

元の TTS を除き、追加した部分だけを効いている順に並べたもの。出典: `docs/VC_1115.md` / `docs/VC_PLAN.md` / `docs/VC_PLAN_1117.md`

### 中心: 内容条件を DiT の入力に足す仕組み

- **内容アダプタと入力射影への加算**
  - 声質を撹乱した入力の WavLM 層 6/9/12 を重み付きで足し合わせ、幅 256 に絞ってから DiT の幅に戻す。それを DiT の入力射影の出力にフレームごとに足す
  - 最後の線形層はゼロから始める (ControlNet と同じ考え方) → 学習の最初は元の TTS と同じ動き。TTS 本体のコードは変えず、入力射影を包むだけ
  - これで「テキスト → 音声」が「音声 → 音声」になる。出力の長さ・タイミング・抑揚・非言語音が、時間の並びを保ったまま入力から伝わる
  - WavLM とコーデック latent がどちらも約 25 Hz なので、長さは線形補間で端数を合わせるだけで済む
- **書き起こしなしの自己教師学習と、その工夫**
  - 「声質を撹乱した自分の発話から、元の発話を復元する」だけを学習する → 書き起こしの点検が要らない
  - 撹乱はピッチ・フォルマント・EQ の 3 種類
  - 声色の参照には同じ話者の**別の**発話を使う (入力の声色をそのまま写す近道を防ぐ)
  - 学習するのは内容アダプタと DiT の LoRA (r=16) だけ。VRAM 8 GB で 1 回 7 分ほど

### 品質を決めている部分

- **テキストを補助に足す仕組み** (テキストを 50% の確率で落として学習、推論は textauto)
  - 内容条件だけだと言葉が崩れる (CER 0.48〜0.67)
  - 音韻はテキスト経路 (ASR の書き起こし)、タイミング・抑揚・非言語音は内容条件、という分担
  - **CER 0.48 → 0.04**。数字の上では一番大きく効いた改善
  - textauto: 書き起こしが絵文字だけの区間 (笑い・息など) ではテキストを使わない → 非言語音を内容条件だけで通すために要る
- **推論時の話者 LoRA**
  - 変換先の声で VC の LoRA を 100 ステップ (数秒) だけ追加で学習する
  - 低い声への変換先との類似度 **0.715 → 0.888**
  - 声色を近づける方法を 6 つ比べて、はっきり効いたのはこれだけ (7 章)

### 補助的な部分

- 自作のスタイルエンコーダを、元の TTS の「声の説明文」の経路に入れる。入力には内容条件とは**別の乱数**で撹乱した版を使い、丸写しを防ぐ
- 複数の参照音声をつなぐ (最大 120 秒): 声色は少し良くなるが、参照を長くすると言葉が崩れやすくなる疑いがある
- 長い入力は無音で区切って変換し、元のタイミングで並べ直す

### 鍵にならなかったもの (比較のネタ)

- audio2audio (SDEdit 方式) と ODE inversion (変換元の latent からノイズを逆算して生成し直す) は、どちらも今の構成を上回る条件がなかった
  - 全部 inversion すると実質テキスト読み上げになる (抑揚の相関 0.49 → 0.16)。途中までの inversion は、声色と抑揚のどちらかしか取れない
  - CFG ありで逆積分するとランダムノイズから生成したのと同じくらい元から離れる (画像の拡散モデルで null-text inversion が要るのと同じ問題)
  - VC モデルで inversion しても通常の VC とほぼ同じ → 内容条件で変換元の構造をすでに受け取っているので、出発点のノイズに構造を持たせても上乗せがない

### まとめの一文 (記事に使える形)

- 技術として鍵になっているのは、**「フレーム単位の内容条件を、ゼロから始めるアダプタで凍結した TTS の入力に足す」構成**と、**それを書き起こしなしの自己教師学習で教える仕組み**の 2 つ
- 実用的な品質は、**テキストとの役割分担** (言葉の明瞭さ、CER 0.04) と **推論時の話者 LoRA** (声色の近さ) の 2 つで決まっている

## 14. 一般的な VC の評価項目での測定結果

出典: `results/vc_eval_v2.json` (12 章の基準値) / `results/vc_eval_lora.json` (話者 LoRA)。
評価セット v2: 120 組 (変換元 30 本 × 変換先 4 人) × 2 シード = 240 件。数値は 240 件の平均。

### 評価項目と、一般的な呼び方との対応

| 一般的な評価項目 | 本研究での指標 | 測り方 |
| :--- | :--- | :--- |
| 話者類似度 (SECS / Speaker Similarity) | `sim_tgt` ↑ / `sim_src` ↓ | WavLM-SV の話者埋め込みのコサイン類似度。変換先の発話 (最大 8 本、LoRA 評価では学習に使っていない発話) / 変換元の音声と比較 |
| 明瞭性 (Intelligibility, CER / WER) | `cer` ↓ | Whisper large-v3-turbo の書き起こしと、変換元の書き起こしの文字誤り率 (1 件ごとに 1.0 で切り詰め) |
| 韻律の保持 (F0 相関 / F0 RMSE) | `f0_corr` ↑ | 話者ごとに正規化した対数 F0 の相関 (長さが同じならフレーム対応、違えば DTW) |
| (独自) 非言語音の保持 | `nv_corr` ↑ / `nv_recall` ↑ | AST の非言語音クラスの確率を 1 秒窓で比較 (6 章) |
| 長さ・タイミング | `dur_ratio` | 変換後 / 変換元 の長さの比 |

### 測っていない項目 (記事で正直に書く)

- **自然性 (MOS / UTMOS などの自動 MOS 予測)**: 未測定。音質は試聴での判断のみ
- **MCD (メルケプストラム歪み)**: 同じ文を変換先が話した正解音声 (パラレルデータ) がないため測れない
- **主観評価 (MOS・ABX・話者類似度の聴取試験)**: 未実施
- **処理速度 (RTF)**: 体系的には未測定。参考値として 6.7 秒の入力を 2.4 秒で変換 (RTF 約 0.36、40 ステップ、話者 LoRA なし)

### 数値を載せるときの注意

- 「未学習」の変換先のうち 6 人は、評価したモデルの学習データに含まれていた (除外は後から)。本当に未学習なのは低い声の 1 人と、変換元の話者のみ → 「参考値」と明記する
- 話者類似度は言葉が崩れた出力ほど高く出る (6 章)。CER と必ず並べて載せる
